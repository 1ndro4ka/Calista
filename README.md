# Calista — Мобильное приложение для поиска участников и формирования команд учебных проектов

<p align="center">
  <strong>Современный кроссплатформенный мобильный сервис для студентов (Android / iOS)</strong>
</p>

---

## 1. Назначение и концепция

**Calista** — это мобильное приложение для поиска участников и формирования команд для учебных проектов, курсовых работ, хакатонов и исследовательских групп.

* **Цель проекта**: Устранить разрозненность студенческого сообщества и упростить процесс сборки сбалансированных команд по необходимым навыкам и ролям.
* **Целевая аудитория**: Студенты университетов и колледжей, учебные команды, кураторы проектных практикумов.

Проект разработан в рамках учебной дисциплины **«ПМ07. Разработка мобильных приложений»** с полным покрытием критериев первого и второго семестров.

## 2. Основной функционал

### Первый семестр (Базовый сценарий):
* **Splash Screen**: фирменная векторная анимация с логотипом Calista и автоматической маршрутизацией на основе статуса сессии.
* **Регистрация**: имя, фамилия, валидный email, надежный пароль (минимум 8 символов), Telegram username (без `@`), выбор минимум 2 ключевых навыков.
* **Авторизация**: вход по Email + Password, обработка ошибок на русском языке, восстановление пароля через Firebase Password Reset.
* **Сохранение сессии**: автоматический вход пользователя между запусками приложения (`Firebase Auth state stream`).
* **Главная страница**: лента новых проектов (`createdAt DESC`), компактное приветствие, строка поиска и кнопка фильтров.
* **Основная навигация**: нижняя панель на 4 раздела («Главная», «Мои проекты», «Заявки», «Профиль»).
* **Профиль пользователя**: ФИО, Telegram (с возможностью прямого перехода в чат), список навыков, курс, специальность, биография.
* **Выход из аккаунта**: подтверждение выхода и сброс сессии.

### Второй семестр (Расширенный функционал и CRUD):
* **Полный CRUD учебных проектов**:
  * **Create**: создание проекта с валидацией названия (5–80 симв.), описания (20–2000 симв.), категории, требуемых навыков (мин. 1), лимита участников (2–8 чел.) и дедлайна. Создатель автоматически регистрируется первым участником проекта с ролью `owner`.
  * **Read**: чтение ленты новых проектов, просмотр созданных и проектов с участием.
  * **Update**: редактирование проекта создателем с валидацией вместимости (запрещено устанавливать максимальный размер меньше текущего количества участников).
  * **Delete**: удаление проекта с каскадной очисткой связанных участников и заявок в Cloud Firestore.
* **Механизм заявок и формирования команды**:
  * Подача заявки кандидатом с опциональным комментарием (до 300 символов).
  * Входящие заявки для создателя проекта с отображением компетенций и Telegram кандидата.
  * Атомарное **принятие** заявки через `Firestore Transactions` (добавление в `project_members`, инкремент `memberCount`, авто-смена статуса на `full` при заполнении, уведомление кандидату).
  * **Отклонение** заявки с уведомлением кандидата.
  * **Отмена** собственной ожидающей заявки кандидатом.
  * Возможность участника **покинуть проект** (создатель защищен от случайного выхода).
* **Поиск и многофакторная фильтрация**:
  * Регистронезависимый локальный поиск по названию, описанию, категории и навыкам.
  * Фильтр по 6 категориям («Разработка», «Дизайн», «Аналитика», «Маркетинг», «Учёба», «Другое»).
  * Фильтр по навыкам, размерам команд (`2–3`, `4–5`, `6+`) и дедлайну (ближайшие 30 дней).
* **Избранное (Favorites)**:
  * Сохранение проектов в закладки в Cloud Firestore (`/users/{uid}/favorites/{projectId}`) с моментальным откликом интерфейса.
* **Внутренние уведомления**:
  * Уведомления о поступлении новой заявки, принятии, отклонении и выходе участника с бейджами и отметкой о прочтении.
* **Редактирование профиля и загрузка аватара**:
  * Изменение данных и выбор фото через `image_picker` с сохранением в Firebase Storage. Обязательное условие сохранения минимум 2 навыков.
* **UI/UX без EMOJI**:
  * Строгий современный минималистичный дизайн Material 3. Использование исключительно векторных Material Icons и SVG-графики.

## 3. Стек технологий

* **Язык**: Dart 3.13+
* **Фреймворк**: Flutter 3.47+ (Android, iOS)
* **Архитектура**: Clean Architecture + Feature-First
* **State Management**: Flutter Riverpod 3.x (`Notifier`, `NotifierProvider`)
* **Навигация**: GoRouter (`StatefulShellRoute`)
* **Бэкенд**:
  * Firebase Authentication (Email & Password)
  * Cloud Firestore (транзакции, пакетная запись, безопасность)
  * Firebase Storage (загрузка и хранение медиа)
* **Вспомогательные библиотеки**:
  * `url_launcher` — открытие Telegram профиля
  * `image_picker` — выбор аватара из галереи
  * `flutter_svg` — рендеринг SVG-логотипа
  * `intl` — русская локализация дат

## 5. Коллекции Cloud Firestore

1. **`users`** (`/users/{uid}`):
   * `uid`, `firstName`, `lastName`, `telegramUsername`, `avatarUrl`, `bio`, `course`, `specialty`, `skills[]`, `createdAt`, `updatedAt`.
   * Подколлекция: `/users/{uid}/favorites/{projectId}`.
2. **`projects`** (`/projects/{projectId}`):
   * `id`, `ownerId`, `title`, `description`, `category`, `requiredSkills[]`, `maxMembers`, `memberCount`, `deadline`, `status` (`open`/`full`/`closed`), `createdAt`, `updatedAt`.
3. **`project_members`** (`/project_members/{projectId}_{userId}`):
   * `projectId`, `userId`, `role` (`owner`/`member`), `joinedAt`, `userName`, `userTelegram`, `userSkills[]`, `userAvatarUrl`.
4. **`applications`** (`/applications/{projectId}_{applicantId}`):
   * `projectId`, `projectTitle`, `applicantId`, `applicantName`, `applicantTelegram`, `applicantSkills[]`, `message`, `status` (`pending`/`accepted`/`rejected`/`cancelled`), `createdAt`, `reviewedAt`.
5. **`notifications`** (`/notifications/{notificationId}`):
   * `recipientId`, `type`, `title`, `body`, `projectId`, `applicationId`, `isRead`, `createdAt`.

Правила безопасности (`firestore.rules`, `storage.rules`) и составные индексы (`firestore.indexes.json`) находятся в корне репозитория.

## 6. Запуск и настройка проекта

### 6.1. Требования:
* Установленный **Flutter SDK** (версия 3.22+ / 3.47+)
* Dart SDK 3.x
* Установленный Android Studio / Xcode для сборки под эмулятор или устройство

### 6.2. Установка зависимостей:
```bash
flutter pub get
```

### 6.3. Конфигурация Firebase:
Для подключения собственного Firebase-проекта выполните:
```bash
# Активация FlutterFire CLI
dart pub global activate flutterfire_cli

# Конфигурация проекта (создаст/обновит firebase_options.dart)
flutterfire configure
```
В консоли Firebase подключите:
* **Authentication** (провайдер: Email/Password)
* **Cloud Firestore**
* **Firebase Storage**

Разверните правила безопасности и индексы:
```bash
# Базовый деплой правил Firestore и индексов (план Spark):
firebase deploy

# При наличии подключенного Cloud Storage (план Blaze):
firebase deploy --only storage
```

### 6.4. Запуск приложения:
```bash
flutter run
```

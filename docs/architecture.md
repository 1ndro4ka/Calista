# Архитектура приложения Calista

## 1. Архитектурный подход

Мобильное приложение **Calista** разработано в соответствии с принципами **Clean Architecture** и модульной организацией **Feature-First**.

### Слои архитектуры

```text
┌────────────────────────────────────────────────────────┐
│                   Presentation Layer                   │
│   (Pages, Reusable Widgets, Riverpod Notifiers/States) │
└───────────────────────────┬────────────────────────────┘
                            │
┌───────────────────────────▼────────────────────────────┐
│                      Domain Layer                      │
│       (Entities, Repository Contracts, Failures)       │
└───────────────────────────┬────────────────────────────┘
                            │
┌───────────────────────────▼────────────────────────────┐
│                       Data Layer                       │
│    (DataSources, Repository Implementations, Mappers)   │
└───────────────────────────┬────────────────────────────┘
                            │
┌───────────────────────────▼────────────────────────────┐
│                    Firebase Backend                    │
│      (Firebase Auth, Cloud Firestore, Cloud Storage)   │
└────────────────────────────────────────────────────────┘
```

### Принципы реализации:
* **Separation of Concerns (Разделение ответственности)**: UI не содержит прямых вызовов Firebase SDK или сетевой логики.
* **Dependency Inversion (Инверсия зависимостей)**: Слой Presentation зависит от абстракций репозиториев Domain слоя, внедряемых через Riverpod providers.
* **Type Safety & Data Immutability**: Все данные строго типизированы через сущности (`UserProfile`, `Project`, `ProjectMember`, `ProjectApplication`, `AppNotification`). Использование `Map<String, dynamic>` ограничено исключительно адаптерами DataSources.
* **Централизованная обработка ошибок**: Исключения Firebase (Auth, Firestore, Storage) перехватываются на уровне Data-слоя и преобразуются в человекопонятные исключения `AppException` с русскоязычными сообщениями без вывода технических кодов.

## 2. Структура проекта (Feature-First)

```text
lib/
├── app/
│   ├── app.dart                   # Корневой MaterialApp.router
│   ├── providers/
│   │   └── app_providers.dart     # Внедрение зависимостей через Riverpod
│   └── router/
│       └── app_router.dart        # Конфигурация GoRouter с Auth Guard
│
├── core/
│   ├── constants/                 # Название, категории, навыки, лимиты валидации
│   ├── errors/                    # Иерархия AppException и ErrorHandler
│   ├── extensions/                # Форматирование дат (intl), BuildContext хелперы
│   ├── theme/                     # AppColors, AppSpacing, AppRadius, AppTypography, AppTheme
│   ├── utils/                     # Хелпер для запуска Telegram (UrlUtils)
│   ├── validators/                # Валидаторы форм (AppValidators)
│   └── widgets/                   # Переиспользуемые UI-компоненты
│
├── features/
│   ├── auth/                      # Регистрация, вход, сброс пароля, Splash
│   ├── home/                      # Главная лента новых проектов, поиск, фильтры
│   ├── projects/                  # CRUD проектов, карточки, просмотр, участники
│   ├── applications/              # Подача, принятие, отклонение, отмена заявок
│   ├── notifications/             # Внутренние уведомления приложения
│   ├── profile/                   # Просмотр и редактирование профиля, фото, Telegram

├── firebase_options.dart          # Конфигурация платформенных параметров Firebase
└── main.dart                      # Точка входа, инициализация Firebase и ориентации
```

## 3. Управление состоянием (State Management)

В качестве библиотеки управления состоянием используется **Flutter Riverpod (3.x)** с современными классами `Notifier` и `NotifierProvider`:

1. **`authControllerProvider`** — управление аутентификацией (вход, регистрация, выход, сброс пароля).
2. **`projectActionControllerProvider`** — управление операциями создания, обновления, удаления проектов и выхода участников.
3. **`applicationsControllerProvider`** — транзакционное принятие, отклонение и отмена заявок.
4. **`profileControllerProvider`** — редактирование данных студента и загрузка аватара в Firebase Storage.
5. **`projectFilterProvider`** и **`searchQueryProvider`** — локальная фильтрация и мгновенный поиск без лишней нагрузки на Firestore.

## 4. Навигация (GoRouter)

* **`StatefulShellRoute.indexedStack`** реализует 4 независимые ветви нижней навигации без сброса состояния экранов при переключении:
  1. `/home` — Главная
  2. `/my-projects` — Мои проекты
  3. `/applications` — Заявки
  4. `/profile` — Профиль
* **Auth Guard (редиректы)**:
  * Неавторизованные пользователи при попытке открыть защищённые экраны автоматически перенаправляются на `/login`.
  * Авторизованные пользователи не могут открыть экран входа или регистрации (перенаправляются на `/home`).
  * Экраны деталей проекта, создания, редактирования и уведомлений открываются поверх нижней панели.

## 5. Дизайн-система и UI/UX

* Светлая тема Material 3 со сдержанной палитрой: глубокий графитовый (`#1E293B`), королевский синий акцент (`#2563EB`), нейтральные фоны (`#F8FAFC`).
* **Категорический запрет на emoji**: вся визуальная коммуникация выполнена через векторные Material Icons и оригинальный SVG-логотип Calista.
* **Состояния экранов**: каждый асинхронный экран явно поддерживает состояния `Loading` (Skeleton Cards), `Empty` (информативные сообщения с действием), `Error` (сообщение + кнопка повтора) и `Success`.

## 3. Теоретический раздел для отчёта по курсовой работе

### 3.1. Предметная область
В современной высшей школе и проектном обучении командная работа является ключевой формой проектной деятельности. Студенты регулярно сталкиваются с проблемой подбора участников для курсовых, дипломных и конкурсных проектов. Традиционные каналы коммуникации (чаты в мессенджерах) страдают от отсутствия структурированности: сложно отслеживать требуемый стек, статус набора и компетенции кандидатов. Приложение **Calista** решает эту проблему за счёт структурированной карточки проекта, прозрачной системы заявок и профилей участников с подтверждённым Telegram.

### 3.2. Архитектура мобильного приложения
Приложение построено на базе **Clean Architecture** (чистая архитектура Роберта Мартина):
* **Presentation**: фреймворк Flutter, страницы, виджеты и контроллеры `Notifier` (Riverpod).
* **Domain**: чистые сущности Dart (`Project`, `UserProfile`, `ProjectApplication`) и интерфейсы репозиториев без внешних зависимостей.
* **Data**: реализации репозиториев, взаимодействие с Cloud Firestore и Firebase Storage, маппинг данных.

### 3.3. Технологический стек
* **Flutter SDK**: высокопроизводительный кроссплатформенный фреймворк с компиляцией в нативный машинный код ARM для Android и iOS.
* **Firebase Authentication**: безопасная авторизация без необходимости поддержки собственного сервера аутентификации.
* **Cloud Firestore**: документная NoSQL база данных реального времени с поддержкой транзакций.
* **GoRouter**: декларативная маршрутизация с поддержкой вложенных стеков навигации (`StatefulShellRoute`).
* **Flutter Riverpod**: реактивное управление состоянием с проверкой зависимостей во время компиляции.
